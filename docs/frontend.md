# Frontend Summary

Two frontends: the main app ([client/](../client/CLIENT.md)) and the embeddable widget
([widget/](../widget/WIDGET.md)).

## Main app (`client/`)
React 19 + React Router 7 SPA built with Vite. Served under a base path (default `/kai`).

### Data-flow layering (enforce this)
```
routes/ (pages) → components/ → stores/ (Zustand) → services/ (axios) → lib/api-client.ts → backend /api/v1
```
- Pages: 11 routes declared in [client/app/App.tsx](../client/app/App.tsx)
  → [ROUTES.md](../client/app/routes/ROUTES.md)
- Components: canvas (XYFlow), metadata-driven node forms, modals, credentials UI, tutorial
  → [COMPONENTS.md](../client/app/components/COMPONENTS.md)
- State: 13 Zustand stores → [STORES.md](../client/app/stores/STORES.md)
- API layer: one service per backend router → [SERVICES.md](../client/app/services/SERVICES.md)
- Utilities/hooks: api-client, runtime config, SSE/log-stream hooks, undo/redo
  → [LIB.md](../client/app/lib/LIB.md)

### Key mechanisms
- **Metadata-driven node UI**: backend `NodeMetadata` renders forms automatically
  (`GenericNodeForm` + `node/fields/*`) — most new backend nodes need zero frontend work.
- **Streaming UX**: SSE hooks paint node execution status on the canvas and stream logs into the
  log terminal and chat.
- **Auth duality**: local JWT and Keycloak OIDC (react-oidc-context); `AuthSynchronizer` keeps
  the Zustand auth store and OIDC session consistent.
- **Runtime config**: `public/config.js` sets `window.VITE_*` at load; `app/lib/config.ts`
  arbitrates between it and build-time Vite env.

### Testing/quality
Vitest (+ Testing Library), jest-axe a11y config, ESLint zero-warning policy,
`npm run typecheck`.

## Widget (`widget/`)
`@kaifusion/widget` — chat UI for embedding finished assistants on any site. npm library build
and standalone `widget.js` (served by backend at `/widget/widget.js`). Embed code generated by
`WidgetExportModal` in the client. Details: [WIDGET.md](../widget/WIDGET.md).
