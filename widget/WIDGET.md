# widget/ — Embeddable Chat Widget

## Folder Purpose
A standalone chat widget (`@kaifusion/widget`) that lets any external website talk to a KAI-Flow
workflow. Distributed two ways: as an npm React library and as a self-contained `widget.js` for
plain `<script>` embedding (also served by the backend at `/widget/widget.js`).

## What This Folder Contains / File-by-File Explanation
- `src/KaiChatWidget.tsx` — the widget component (chat UI, markdown/KaTeX rendering, syntax
  highlighting, animations via motion).
- `src/embed.tsx` — standalone bootstrap for the script-tag build.
- `src/config.ts` — widget configuration handling (API URL, workflow/session parameters).
- `src/index.ts` / `src/index.css` — library entry + styles.
- `vite.config.ts` — **library build** (ES + CJS, `vite-plugin-dts` type declarations, CSS
  injection) → `dist/` for npm.
- `vite.config.standalone.ts` — **standalone build** → single embeddable bundle
  (`npm run build:standalone`).
- `package.json` — name `@kaifusion/widget` v1.1.0; peer deps React 18/19.
- `README.md` — upstream usage docs (npm install, props, HTML & MkDocs embedding examples).

## Important Files
`src/KaiChatWidget.tsx`, the two Vite configs.

## Relationship With Other Folders
- Consumed by `client/` as a dependency (`client/app/components/KaiChatWidget.tsx` wraps it).
- `backend/main.py` mounts a `widget/` directory as static files at `/widget` (Docker:
  `/app/widget`; local: this folder) — the standalone bundle is what gets served.
- Embed snippets are generated by `client/app/components/modals/WidgetExportModal.tsx`.

## How This Folder Fits Into the AI Workflow
The deployment surface: an end user chats through the widget → backend chat/workflow endpoints →
engine executes the workflow → response streams back into the widget.

## Developer Notes
- `npm run dev` for local development; `npm run build` (library) and `npm run build:standalone`
  (script-tag bundle).
- README shows both React usage (props) and HTML/MkDocs integration.

## Things to Be Careful About
- Package name is `@kaifusion/widget` (legacy branding) — the root README's mention of
  `@kaiflow/widget` does not match; use `@kaifusion/widget`.
- Keep widget API calls compatible with backend chat/execution endpoints — the widget may be
  embedded on third-party sites that update rarely.
- The pre-built bundle served at `/widget` must be rebuilt after source changes (the repo does
  not automate this). This part is not clearly defined in the project.
